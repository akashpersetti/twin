## Project: RepoModernizer (Autonomous Codebase Migration Agent)
RepoModernizer is an autonomous codebase migration agent live at repo-modernizer.akashpersetti.com. Akash built a 5-node LangGraph state machine (ingest, install deps, plan, migrate-file loop, finalize) that plans a file-by-file migration from a natural-language goal, rewrites each file with an LLM, and gates any diff above a risk threshold behind a human-in-the-loop interrupt() before it touches disk. He computed diffs from known-good before/after content rather than trusting LLM-authored diffs, with bounded retries and Bedrock primary/fallback failover on transient errors, plus guardrails (forbidden paths, max changed lines, no deletions) and a hard per-task cost cap evaluated against estimated spend before each call rather than after. He fixed a concurrency defect where repeated approve clicks produced 6–9 duplicate commits, using a pending-interrupt check plus an atomic DynamoDB claim so exactly one resume wins; he verified by inducing crashes mid-migration and confirming correct file state and no duplicate commits on resume. He root-caused a git apply rejection affecting roughly a third of files (10 of 31, consistent across two batches) to diff generation force-padding a trailing newline onto both sides, which misrepresents files that genuinely lack one—invisible to Python fixtures, fatal on a real JS repo. He fixed upstream by normalizing before diffing rather than hand-rolling the \No newline at end of file markers difflib does not support. He ran 16 real migrations at $0.0023 and 4.8 minutes average per run on a deliberately NAT-free stack (API Gateway, Lambda via Mangum, SQS, one-shot Fargate, EFS-mounted workspace, DynamoDB checkpointing) after pricing showed a NAT gateway would cost more per month than the bursty workloads it served; provisioned via Terraform and GitHub Actions OIDC, 96 passing tests, no long-lived AWS credentials.

## Project: TerraformAgent (Multi-Agent IaC Generator)
TerraformAgent is a multi-agent infrastructure-as-code generator live at terraform-agent.akashpersetti.com. Akash built a 6-node LangGraph pipeline (orchestrator, researcher, parallel domain subagents, aggregator, reviewer, evaluator) that turns a natural-language infrastructure request into validated Terraform, with a conditional edge that reruns only the domains a review flags, up to a capped number of targeted retries. He gated output on a real compiler rather than a model's opinion of its own work: the evaluator writes generated code to disk and runs terraform fmt and terraform validate against a provider cache baked into the Docker image, reaching full offline validation by copying the read-only cache into a writable path once per execution environment. He instrumented the targeted-retry loop and measured it across 10 real prompts in both modes: zero pass-rate improvement (the same 4 of 10 passed) at 46s to 145s average wall time. He root-caused to a severity classifier that treats any wildcard resource as blocking—firing on 10 of 10 tasks so the loop always engages and always maxes out—plus cross-domain reference errors that single-domain regeneration cannot fix by construction. He hardened review with a multi-LLM security fan-out (reusing the mcp-second-opinion pattern) querying OpenAI and Anthropic in parallel and blocking on any veto, degrading to single-LLM review on provider outage. He documented its real limits: it caught an IAM policy granting kms:Encrypt on Resource: "*" precisely and then failed to repair it across three regenerations, and it cannot distinguish an intentionally public S3 bucket for static hosting from an accidentally public one. He deployed the containerized service on Lambda and Step Functions with JWT authentication, DynamoDB state, SQS failure handling, and Secrets Manager; provisioned through Terraform and GitHub Actions OIDC, with 94 passing tests and no long-lived AWS credentials.

## Project: EvalBench (Multi-Provider LLM Evaluation Platform)
EvalBench is a multi-provider LLM evaluation platform live at evalbench.akashpersetti.com. Akash architected a pluggable-suite eval harness where every benchmark emits one shared MetricRecord contract persisted to a single JSON-column table, so adding a suite is a three-file change that never touches the runner, store, or dashboard core. He shipped three benchmark suites on that harness: structured-output reliability (schema-valid rate, retries-to-valid, retry-only cost accounting), latency/cost with pairwise judge scoring, and RAG with recall@k, nDCG@k, and faithfulness across swappable chunking strategies. He ran 27 evaluation runs across 75 tasks and 7 model/config variants, surfacing an 8-point first-attempt schema-validity gap between providers on structured output and a p95 latency spread of 6.0s vs 9.4s, and found that semantic chunking doubled RAG context precision (0.13 to 0.26) over fixed-window at comparable faithfulness. He hand-implemented statistically honest aggregation, attaching 95 percent Wilson intervals to proportions and binomial order-statistic intervals to p95 latency, with per-metric sample sizes on every leaderboard cell so no aggregate renders as a bare mean. He deployed serverless on AWS: dual Lambda (API plus async runner), API Gateway v2, CloudFront, DynamoDB run tracking, and SES magic-link auth, backed by 262 passing tests using injected LiteLLM callables and temporary SQLite databases, running the full suite with no provider calls or model cost.
